# Сети: как программы разговаривают

## Адрес, порт, протокол

Чтобы две программы поговорили, нужно три вещи: куда (IP-адрес машины), кому (порт, число от 0 до
65535, по нему различают программы на одном адресе) и как (протокол: кто начинает, что считается
ответом). Адрес — это дом, порт — это квартира. TCP, UDP и HTTP — это протоколы.

- `127.0.0.1` (`localhost`) всегда означает «этот же компьютер», пакет в сеть не выходит.
  На занятии всё делается на нём: не мешает чужим и работает без интернета.
- Известные порты: 22 ssh, 80 http, 443 https. Список лежит в `/etc/services`.
- Сервер на `0.0.0.0` виден всей сети, на `127.0.0.1` только мне. Для учёбы только второе.
  `python3 -m http.server` без `--bind` слушает `0.0.0.0`, я это видел в `ss`.

```bash
ip -brief addr      # мои адреса
ip route            # шлюз (default via ...) и соседние сети
ss -ltnp            # кто слушает TCP-порты, с именем процесса
cat /etc/hosts      # имена без DNS
```

В `192.168.1.81/24` число 24 — это маска: первые 24 бита общие, то есть соседи отличаются только
последним числом. Всё, что не в моей сети, уходит на шлюз.

> **Запомнить:** сокет — это обычный дескриптор, как 0, 1, 2. `read` и `write` работают так же, как с
> файлом. В `ss -ltnp` его видно как `fd=3`.

## TCP: как звонок

Порядок вызовов фиксирован.

| Сервер | Клиент |
| --- | --- |
| `socket()`: завёл телефон | `socket()` |
| `bind()`: повесил на порт | |
| `listen()`: включил звонок | |
| `accept()`: взял трубку | `connect()`: набрал номер |
| `read()` / `write()` | `write()` / `read()` |
| `close()` | `close()` |

Разница только в одном: сервер делает `bind`, `listen` и `accept`, клиент `connect`. Поэтому сервер
запускается первым, иначе `connect` получит `Connection refused`.

Рукопожатие из трёх шагов: клиент шлёт SYN, сервер отвечает SYN-ACK, клиент подтверждает ACK.
Обе стороны проверили, что слышат друг друга. После этого каждый кусок данных подтверждается, а
потерянный отправляется заново, поэтому TCP надёжен. В `tcpdump` это видно как флаги `S`, `S.`, `.`,
но он требует root, поэтому на практике я смотрел `strace` и `ss`.

```bash
./echo_server 8080 &
./echo_client 127.0.0.1 8080 "привет"
ss -ltnp | grep 8080
strace -e trace=connect,read,write ./echo_client 127.0.0.1 8080 "тест"
```

В `strace` сетевое соединение появляется строкой `connect(3, {... sin_port=htons(8080) ...}, 16) = 0`.

> **Грабли:** `read` может вернуть меньше, чем ждёшь, поэтому читать нужно в цикле до 0. И наоборот:
> `read` на сокете вернёт 0 только когда другая сторона закроет свою половину. Мой `http_get` к
> эхо-серверу повис именно так: сервер ждал конца запроса, клиент ждал конца ответа, а
> `shutdown(sock, SHUT_WR)` ни один не вызвал.

## UDP: как открытка

Нет соединения и рукопожатия, нет подтверждений, порядок не гарантирован. Потерялся пакет, и никто
не заметил. Зато быстро. Подходит там, где потеря одного пакета не страшна: DNS, игры, голос и
видео. В коде вместо `listen` и `connect` стоят `sendto` и `recvfrom`, адрес получателя указывается
в каждом пакете.

```bash
./udp_echo server 9000 &
./udp_echo client 9000 "проверка UDP"
```

## HTTP руками

HTTP — это текст поверх TCP. Запрос:

```text
GET / HTTP/1.0
Host: 127.0.0.1:8001

```

Каждая строка кончается `\r\n`, пустая строка в конце значит «я закончил». Ответ: статус, заголовки,
пустая строка, тело. Коды: 200 нашёл, 404 такого файла нет, 500 у сервера ошибка.

```bash
python3 -m http.server 8001 --bind 127.0.0.1 &
./http_get 127.0.0.1 8001 /nope
curl -si http://127.0.0.1:8001/
```

`curl` делает то же самое, что мой `http_get`, но за меня. Понимать, что внутри, всё равно нужно.

## Когда сеть не работает: пять проверок

Порядок от «кто я» к «куда иду» и к приложению. Если пропустить первые шаги, можно полчаса искать не
там.

1. `ip addr`: есть ли у меня адрес.
2. `ip route`: знаю ли я, куда слать пакеты за пределы своей сети.
3. `ss -ltn`: слушает ли нужный порт сервер, и не запустился ли он на другом порту.
4. `nc -z -w 2 ХОСТ ПОРТ`: пускают ли на этот порт.
5. `curl -i`: отвечает ли приложение осмысленно.

Сначала всё равно читать текст ошибки, в нём уже почти всё написано:

| Ошибка | Что значит |
| --- | --- |
| `Connection refused` | машина ответила сразу, на порту никто не слушает |
| `Connection timed out` | ответа нет вообще, до адреса не дойти |
| `Name or service not known` | не разобралось имя |
| `Address already in use` | при `bind`: порт занят |

> **Запомнить:** `Connection refused`, таймаут и `Address already in use` — это три разных причины и
> три разных лекарства. «Сеть не работает» сначала надо свести к одной из этих строк.

## Чек-лист сетевой программы

- Слушать только нужное: `127.0.0.1` для учёбы.
- Проверять код возврата `bind`, `listen`, `connect`: порт мог быть занят.
- Не верить одному `read`, читать в цикле, пока не 0.
- Закрывать дескрипторы от `socket` и `accept`: иначе они рано или поздно кончатся (`ulimit -n`).
- Читать текст ошибки: `perror` уже сказал, что не так.
- Смотреть со стороны: `ss`, `strace`, `nc` показывают то, чего не видно из кода.
