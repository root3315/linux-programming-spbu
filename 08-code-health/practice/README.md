# Практики занятия 8

Все четыре практики на одном проекте из архива Chapter 08 преподавателя: функция
`make_greeting` с переполнением буфера, тесты, фаззер, учебный «грязный» файл для
линтеров и Makefile с целями `test`, `coverage`, `sanitize`, `fuzz`, `tidy`. Работал как на
слайдах: распаковал архив, скопировал `Chapter08/project` в `~/health-lab` и шёл по
практикам подряд, каждая продолжает предыдущую. В папках ниже только моё: сессии с
командами и выводом и файлы, которые я поменял.

Запускал в контейнере с Ubuntu 24.04:

```bash
docker run --rm -it -v "${PWD}:/work" -w /work ubuntu:24.04 bash
apt update && apt install -y build-essential cmake cppcheck clang-tidy python3 file
```

`python3` нужен только для длинного имени в практике 3 (`python3 -c 'print("A"*100)'`).

## Практика 1. Свои тесты

Запустить `make test` и проверить код выхода. Добавить два теста: имя `"СПбГУ"` даёт
`"Hello, СПбГУ!"`, а для имени из 64 символов посмотреть, что вернёт функция. Сломать функцию
(убрать `"!"`), убедиться, что тесты краснеют, починить и снова посмотреть `echo $?`.
Критерий: тесты краснеют на сломанном коде и зеленеют на исправленном. Вопрос со слайда:
почему тест на длинное имя не проходит на исходном коде.

Решение: [01-tests/session.md](01-tests/session.md), мой
[test_greeting.c](01-tests/test_greeting.c).

## Практика 2. Закрыть белые пятна

`make coverage`, записать процент строк, найти в `greeting.c.gcov` строки с `#####`.
Добавить тест на «громкое» приветствие: `"!Аня"` даёт `"HELLO, Аня!!!"`. Снова
`make coverage` и сравнить. Объяснить, почему тест на `"!Аня"` проходит, а на длинное имя
нет. Критерий: объяснить, почему 100% покрытия и «код без ошибок» — разные утверждения.

Решение: [02-coverage/session.md](02-coverage/session.md), мой
[test_greeting.c](02-coverage/test_greeting.c). Было 69.23%, стало 100%.

## Практика 3. Санитайзер

`make sanitize`: по слайду тесты проходят и отчёта нет. Запустить
`./build/sanitize-app` с именем из 100 букв, прочитать отчёт (какая строка, какой размер
записи). Собрать без санитайзера, повторить и объяснить, почему ошибку не видно.
Критерий: показать строку, на которую указывает санитайзер, и объяснить, чем она опасна.

Решение: [03-sanitizer/session.md](03-sanitizer/session.md). Своих файлов нет. С моим
тестом из практики 1 `make sanitize` красный сразу, это там разобрано.

## Практика 4. Фаззер и исправление

`make fuzz` и записать, на какой попытке упало. Заменить `strcpy`/`strcat` на `snprintf`
с размером буфера, вернуть `-2`, если строка не влезла, дописать тест на длинное имя.
`make test` и `make fuzz` должны стать зелёными. В конце `make tidy`: что осталось в
линтере. Критерий: фаззер больше не падает, но это не доказательство отсутствия ошибок.

Решение: [04-fuzz-fix/session.md](04-fuzz-fix/session.md), исправленный
[greeting.c](04-fuzz-fix/greeting.c).

## Как повторить

Архив `chapter08.tar.gz` распаковать в папку `practice/` (в репозитории его нет, это
материалы преподавателя), дальше из неё:

```bash
cp -r Chapter08/project health-lab && cd health-lab
sed -i 's/\r$//' Makefile CMakeLists.txt .gitignore */*.c */*.h
cp ../02-coverage/test_greeting.c tests/                  # тесты из практик 1–2
make test; make -i coverage; make -i sanitize; make fuzz   # до исправления
cp ../04-fuzz-fix/greeting.c src/
make test && make coverage && make sanitize && make fuzz   # после
```
