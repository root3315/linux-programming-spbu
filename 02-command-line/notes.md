# Работа с командной строкой в Linux

Весь курс дальше идёт через терминал: gcc, make, cmake, git, docker. Ниже то, что я хочу
держать в голове. Примеры проверены в контейнере на Ubuntu 24.04 под пользователем `stepan`.

## Терминал и оболочка

Это два разных слоя. Терминал (gnome-terminal, konsole, xterm) только рисует символы и
передаёт нажатия клавиш. Команды понимает оболочка, программа, которая запущена внутри
терминала. Проверить, какая оболочка работает сейчас и какая назначена при входе:

```bash
echo $0
echo $SHELL
```

```text
-bash
/bin/bash
```

Минус в `-bash` значит, что это оболочка входа (login shell).

| Оболочка | Чем отличается |
|---|---|
| sh | Bourne shell, исходная POSIX-база |
| bash | стандарт в Linux, POSIX плюс расширения |
| zsh | сильное автодополнение, темы (Oh My Zsh) |
| fish | подсветка синтаксиса из коробки, не POSIX |
| csh / tcsh | синтаксис в стиле C |
| ksh | Korn shell, смесь sh и csh |

### POSIX

POSIX фиксирует интерфейсы, утилиты и поведение оболочки для Unix-подобных систем. Скрипт,
написанный по POSIX, переносится между дистрибутивами и Unix-подобными системами. Что в bash
есть, а в POSIX нет: массивы, `[[ ... ]]` (в POSIX только `[ ... ]`), подстановка процесса `<(...)`.

> **Грабли:** скрипт с `#!/bin/bash` не обязан работать в `sh`, и наоборот. В Ubuntu `sh` —
> это dash, он строже bash. Строка `#!/bin/sh` в начале скрипта — обещание писать переносимо.

## Приглашение и история

`stepan@devbox:~$` читается так: кто, на какой машине, в каком каталоге. `~` — домашний
каталог, `$` — обычный пользователь, `#` — root.

Что экономит время:

- Tab дополняет команду или путь; если не уверен, что файл существует, жму Tab;
- стрелки вверх и вниз листают историю, Ctrl+R ищет по ней;
- `!!` повторяет последнюю команду, `!$` подставляет её последний аргумент, Alt+. делает
  то же самое прямо в строке;
- `history | grep sleep` находит давнюю команду с номером.

Проверил `!!` и `!$` в интерактивном bash. Оболочка сначала печатает развёрнутую команду:

```text
stepan@devbox:~$ ls /etc/hostname
/etc/hostname
stepan@devbox:~$ !!
ls /etc/hostname
/etc/hostname
stepan@devbox:~$ cat !$
cat /etc/hostname
devbox
```

Горячие клавиши для процессов: Ctrl+C посылает SIGINT (прервать), Ctrl+Z посылает SIGTSTP
(приостановить), Ctrl+D вообще не сигнал, а конец ввода (EOF). После Ctrl+C у `sleep 50`
код возврата `echo $?` был 130 = 128 + 2, где 2 — номер SIGINT.

## Файловая система и навигация

В Linux нет дисков C: и D:. Есть одно дерево от `/`, а разделы подключаются в точки
монтирования. Описание стандарта FHS: `man hier`.

| Каталог | Что там |
|---|---|
| /bin | основные утилиты (ls, cp, mv, cat, bash) |
| /etc | конфигурация системы |
| /home | домашние каталоги пользователей |
| /var | меняющиеся данные: логи, кэши, очереди |
| /usr | программы и библиотеки пользовательского уровня |

В Ubuntu 24.04 `/bin` уже не отдельный каталог: `ls -ld /bin` показывает
`/bin -> usr/bin`, симлинк.

Три команды на каждый день: `pwd` (где я), `cd` (перейти), `ls` (что здесь).

| Команда | Куда |
|---|---|
| `cd` | в домашний каталог |
| `cd ..` | на уровень выше |
| `cd -` | в предыдущий каталог (и печатает его) |
| `cd ~/proj` | в proj внутри домашнего |
| `cd /` | в корень |

Ключи `ls`: `-l` подробно, `-a` со скрытыми, `-h` размеры в K/M, `-t` по времени.
`ls -la` и `ls -lah` — самые частые комбинации.

## Файлы и каталоги

| Команда | Что делает |
|---|---|
| `touch` | создать пустой файл или обновить время изменения |
| `mkdir -p` | создать каталог со всей цепочкой родителей |
| `rmdir` | удалить пустой каталог |
| `rm`, `rm -r`, `rm -f` | удалить файл, каталог, без вопросов |
| `cp`, `cp -r` | копировать файл, каталог |
| `mv` | переместить или переименовать |

```bash
mkdir -p lab/src
cd lab
touch main.c notes.md
cp main.c main.c.bak
mv notes.md todo.md
ls -F
rm -rf src
```

```text
main.c  main.c.bak  src/  todo.md
```

> **Грабли:** `rm -rf` не спрашивает и не кладёт в корзину. Лишний пробел в пути — и каталога
> нет. Перед удалением: `pwd`, затем `ls` по той же маске, и только потом `rm`. Если команда
> умеет `--dry-run`, сначала запускаю с ним, а в скрипте вместо опасной команды сначала ставлю
> `echo`.

## Просмотр файлов

`cat` выводит файл целиком, `less` листает постранично (`/` — поиск, `q` — выход),
`head` и `tail` показывают первые и последние 10 строк (`-n N` — сколько), `tail -f` следит
за дописыванием в лог, `wc` считает строки, слова и байты.

```bash
head -n 3 /etc/passwd
wc -l /etc/passwd
```

```text
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
20 /etc/passwd
```

Для всего длиннее экрана лучше `less`: он не заливает терминал.

## Поиск: find и grep

`find` ищет файлы по имени, типу, размеру, времени, обходя дерево каталогов. `grep` ищет
строки внутри файлов по шаблону (регулярному выражению). Их легко спутать.

```bash
find ~ -name "*.txt"
find /var/log -type f -size +10M
grep -rn "TODO" ~/projects/
grep -c "error" app.log
```

Полезные ключи grep: `-r` рекурсивно по каталогу, `-n` номера строк, `-l` только имена
файлов, `-c` число совпадений, `-i` без учёта регистра. Связка двух команд:

```bash
find ~/project -type f -exec grep -l "linux" {} +
```

> **Запомнить:** grep по умолчанию различает регистр. В файле со строками `hello linux` и
> `Hello, Linux!` команда `grep -n linux` нашла только первую, `grep -in linux` — обе.

## Конвейеры и перенаправление

Вывод одной команды становится вводом следующей. Маленькие программы делают одно дело и
соединяются через текст.

| Оператор | Смысл |
|---|---|
| `>` | вывод в файл с перезаписью |
| `>>` | дописать в конец |
| `<` | ввод из файла |
| `\|` | конвейер |
| `2>` | поток ошибок в файл |
| `2>&1` | ошибки туда же, куда обычный вывод |
| `&&` / `\|\|` | выполнить при успехе / при неудаче |

```bash
ls -l /etc | grep -c conf
ls /nonexist 2> err.txt
cat err.txt
false && echo yes || echo no
```

```text
13
ls: cannot access '/nonexist': No such file or directory
no
```

## Процессы и сигналы

Процесс — выполняющаяся программа: у него есть PID, владелец, состояние, потребление CPU и
памяти. `ps aux` даёт снимок всех процессов, `top`/`htop` показывают их в реальном времени,
`pgrep -a имя` ищет PID по имени.

`kill PID` посылает сигнал, по умолчанию SIGTERM. Номера проверил через `kill -l`:

| Сигнал | Номер | Откуда |
|---|---|---|
| SIGINT | 2 | Ctrl+C |
| SIGKILL | 9 | `kill -9`, перехватить нельзя |
| SIGTERM | 15 | `kill` без ключа, можно перехватить |
| SIGTSTP | 20 | Ctrl+Z |

`kill -9` — крайняя мера: процесс не успевает закрыть файлы и сохранить данные. Сначала
обычный `kill`.

## Фоновые задания

- `команда &` сразу запускает в фоне, bash печатает номер задания и PID;
- Ctrl+Z приостанавливает текущую команду, `bg` продолжает её в фоне;
- `jobs` (`jobs -l` с PID), `fg %1` — вернуть на передний план, `kill %1` — сигнал заданию;
- `nohup команда > log.txt 2>&1 &` — процесс переживёт закрытие терминала;
- `disown` убирает задание из списка оболочки.

Как это выглядело у меня:

```text
stepan@devbox:~$ sleep 100
^Z
[1]+  Stopped                 sleep 100
stepan@devbox:~$ bg %1
[1]+ sleep 100 &
stepan@devbox:~$ jobs
[1]+  Running                 sleep 100 &
stepan@devbox:~$ kill %1
stepan@devbox:~$ jobs
[1]+  Terminated              sleep 100
```

## Редакторы

### nano

Все сочетания написаны внизу экрана, `^` там означает Ctrl. Хватает для быстрой правки
конфига на чужом сервере.

| Клавиши | Действие |
|---|---|
| Ctrl+O | сохранить (потом Enter, чтобы подтвердить имя) |
| Ctrl+X | выйти |
| Ctrl+K / Ctrl+U | вырезать / вставить строку |
| Ctrl+W | поиск |
| Alt+/ | в конец файла |

### vi / vim

Три режима: нормальный (по умолчанию, клавиши — команды), вставки (`i`, выход по Esc) и
командный (`:`). В нормальном режиме: `hjkl` — перемещение, `dd` — удалить строку, `yy` —
скопировать строку, `p` — вставить после текущей, `u` — отменить, `gg`/`G` — в начало/конец
файла. `ggyG` копирует весь файл. `:w` — записать, `:q` — выйти, `:wq` — оба, `:e файл` —
открыть другой файл.

> **Запомнить:** выход без сохранения — Esc, потом `:q!`. Выучить до первого запуска vim.

В Ubuntu 24.04 `vi` — это `vim.tiny`, полного vim нет, пока не поставишь пакет `vim`.
Базовые команды выше в нём работают.

## Справка

`man ls` — полное руководство, `man 2 open` — раздел 2, системные вызовы. `ls --help` —
краткая справка от самой программы. Для встроенных команд оболочки (`cd`, `jobs`, `kill`)
есть `help cd`. Узнать, что это за команда: `type cd` ответит `cd is a shell builtin`,
`which ls` — `/usr/bin/ls`. `tldr` даёт примеры вместо теории, но его надо ставить отдельно.

В Docker-образе Ubuntu `man ls` вместо страницы пишет, что система минимизирована, и
предлагает `unminimize`. В контейнере я обходился `--help` и `help`.
