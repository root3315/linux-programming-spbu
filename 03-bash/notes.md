# Bash: от команды к автоматизации

Лекция-практикум: короткая теория, демонстрации и четыре практики по ходу. Правило занятия:
сначала предсказать результат, потом выполнить, потом проверить. Все упражнения делаются в
`~/bash-lab`, который не жалко удалить целиком. Вывод ниже снят в контейнере с Ubuntu 24.04
(bash 5.2.21) под обычным пользователем `stepan`.

## Терминал, оболочка, команда

Терминал показывает текст, Bash читает строку и запускает программы, программа делает работу.
Какая оболочка запущена: `echo $0`, её процесс: `ps -p $$`.

Команда разбирается на слова по пробелам: `ls -lah ~/bash-lab` — имя программы, опции,
аргумент. Имя с пробелом без кавычек превращается в два аргумента. В приглашении
`stepan@lab:~$` видно пользователя, узел и каталог; `$` у обычного пользователя, `#` у root.

Кто на самом деле выполнит имя, показывают `type` и `command -V`:

```text
stepan@lab:~$ type cd
cd is a shell builtin
stepan@lab:~$ type -a ls
ls is aliased to `ls --color=auto'
ls is /usr/bin/ls
ls is /bin/ls
```

### Код возврата и списки команд

Каждая команда возвращает число: 0 значит успех, всё остальное ошибка. Смотреть в `$?`, он
хранит код только последней команды. `test -f file` молчит и возвращает 0, если файл есть;
`ls missing` вернул 2.

| Запись | Когда выполнится правая часть |
|---|---|
| `a; b` | всегда, итоговый код от `b` |
| `a && b` | только если `a` вернула 0 |
| `a \|\| b` | только если `a` вернула не 0 |
| `a &` | `a` уходит в фон, `b` сразу |
| `(a; b)` | обе в подоболочке, `cd` внутри не меняет текущий каталог |

Перед `&&` и `||` надо спросить себя, что вернёт левая команда.

### Справка без браузера

`ls --help` для быстрого списка опций, `man ls` для полного описания (`/слово` ищет, `n`
следующее, `q` выход), `help cd` для встроенных команд Bash. Если имя забыл,
`apropos "copy file"` найдёт `cp` и `install`. Tab дополняет имена, `history` показывает
историю, `!!` повторяет последнюю команду.

> **Грабли:** в Docker-образе `ubuntu:24.04` вместо `man pwd` печатается «This system has been
> minimized…». Образ урезан, страниц нет. Лечится командой `unminimize`, после неё ещё
> `apt install man-db`.

## Пути и раскрытие имён

Абсолютный путь начинается с `/`, относительный считается от текущего каталога. `.` сам
каталог, `..` родитель, `~` домашний, `cd -` возвращает в предыдущий каталог и печатает его.

До запуска программы Bash сам переписывает строку, программа получает уже результат:

| Запись | Во что раскроется |
|---|---|
| `*.txt` | имена файлов по шаблону |
| `?lpha.txt` | один любой символ на месте `?` |
| `{red,green,blue}.log` | три слова, файлов при этом может и не быть |
| `$HOME`, `$(pwd)`, `$((2+3))` | значение переменной, вывод команды, число |

Если шаблон ни с чем не совпал, Bash оставляет его как есть: `printf '%s\n' *.pdf` печатает
`*.pdf`. Это важно в циклах по файлам.

> **Грабли:** на слайде сказано, что `.*` раскрывается в `.` и `..`. В bash 5.2 по умолчанию
> включён `shopt globskipdots`, и `.*` дал только `.secret`. Но `sh` в Ubuntu это dash, и там
> `.*` по-прежнему включает `.` и `..`. Так что `rm -rf .*` опасен в любом случае.

### Кавычки и экранирование

В двойных кавычках подстановки работают, но пробелы остаются внутри одного аргумента. В
одинарных ничего не подставляется. Без кавычек значение с пробелом разваливается:

```text
stepan@lab:~$ name='Linux User'
stepan@lab:~$ printf '<%s>\n' "$name"
<Linux User>
stepan@lab:~$ printf '<%s>\n' $name
<Linux>
<User>
```

`\$` даёт буквальный доллар, `\\` одну обратную черту, `\` в конце строки переносит команду
на следующую строку (после него не должно быть пробела). `--` отмечает конец опций: файл
`-notes.txt` без него `ls` пытается разобрать как опции и падает на `invalid option -- 'e'`.

### printf вместо echo

`printf 'ФОРМАТ' аргументы…`: `%s` строка, `%d` целое, `%.2f` два знака, `%5s` ширина 5
вправо, `%-8s` ширина 8 влево, `%05d` ведущие нули, `%x`/`%o` шестнадцатеричное и
восьмеричное, `%%` знак процента. Ширина минимальная: длинное значение не обрезается.

Оболочка не превращает `\n` в перевод строки, это делает сама программа. `printf 'a\nb'`
даёт две строки, `echo "a\nb"` печатает `a\nb` буквально, `echo -e` зависит от оболочки.
`$'a\nb'` разбирает уже Bash. Проверить, что реально ушло, можно через `od -c`. Для
сценариев беру `printf`.

## Файлы, права, поиск

Смотреть: `cat` для маленького файла, `less` для большого, `head -n`, `tail -n`, `tail -f`
для растущего журнала, `file` для типа, `wc -l` для числа строк, `cat -A` для невидимых
символов. Создавать и двигать: `mkdir -p a/b`, `touch`, `cp -r`, `mv`, `rm -i`, `rmdir`.
Перед удалением: `pwd`, `ls -la`, потом действие, потом проверка.

Права `rwx` для владельца, группы и остальных. `chmod 755 run.sh` то же, что `rwxr-xr-x`;
символьно `chmod u+x`, `chmod u-w`. Для каталога `x` значит право в него войти. Право `x`
на файле нужно для запуска `./file`, а `bash file` работает и без него.

Ядро проверяет только один класс: если я владелец, смотрятся биты владельца, даже если у
группы права шире. На практике файл `-r--rw-r--` мне, владельцу, записать не дал
(`Permission denied`), хотя группа писать может.

`find . -type f -name '*.c'` ищет файлы по дереву, `grep` ищет строки: `-i` без регистра,
`-n` номера строк, `-r` рекурсивно, `-w` целое слово, `-c` число строк, `-q` только код.

## Редакторы

Файл можно создать без редактора: `printf '...' > f` перезаписывает, `>>` дописывает,
`cat > f <<'EOF' … EOF` пишет блок как есть. В nano сохранение `Ctrl+O`, Enter, выход
`Ctrl+X`. vim открывается в режиме команд: `i` вход в ввод, `Esc` обратно, `:wq` сохранить
и выйти, `:q!` выйти без сохранения. После аварии остаётся `.file.swp`, восстановление
`vim -r file`. `crontab -e` и `git commit` открывают редактор из `EDITOR`/`VISUAL`. В
урезанном контейнере vim может не быть: у меня был только `vi`, проверял `command -v`.

## Потоки и конвейеры

У программы три потока: stdin (0), stdout (1), stderr (2). Конвейер `a | b` передаёт только
stdout, ошибки идут мимо на экран.

| Запись | Смысл |
|---|---|
| `cmd > f` | создать или перезаписать (файл очищается до запуска) |
| `cmd >> f` | дописать в конец |
| `cmd < f` | читать вход из файла |
| `cmd 2> f` | только stderr в файл |
| `cmd 2>&1` | stderr туда же, куда stdout |
| `cmd \| tee f` | показать и сохранить |

Типовой разбор журнала: `cut -d' ' -f1 app.log | sort | uniq -c | sort -nr`. `uniq`
схлопывает только соседние строки, поэтому `sort` перед ним обязателен.

## Сценарии

Запуск: `bash s.sh` (shebang не читается, `x` не нужен), `./s.sh` (нужны shebang и `x`),
`source s.sh` (выполняется в текущей оболочке, переменные остаются). Проверил: после
`bash v.sh` переменная `x` пустая, после `source v.sh` в ней `42`.

Shebang `#!/usr/bin/env bash` ищет bash в `PATH`. Ядро читает первую строку при `execve`.

> **Грабли:** `#!/usr/bin/env bash -e` не работает: env получает одно слово `bash -e` и
> пишет `No such file or directory`, код 127. Сам env подсказывает `-S`:
> `#!/usr/bin/env -S bash -e` работает. И второе: файл с переводами строк CRLF из
> Windows не запускается через `./`, ядро ищет интерпретатор `/bin/bash\r` («cannot execute:
> required file not found»). `file` в таком случае пишет «with CRLF line terminators».

Начало сценария:

```bash
#!/usr/bin/env bash
set -euo pipefail
```

`-e` останавливает сценарий на ошибке, `-u` делает ошибкой обращение к неопределённой
переменной, `pipefail` даёт ненулевой код конвейеру, если упало любое звено. Без него
`false | true` возвращает 0, с ним 1. `-e` не срабатывает в условии `if` и в списках
`&&`/`||`: там ненулевой код считается частью логики.

> **Запомнить:** `((n++))` при `n=0` возвращает код 1, потому что значение выражения было 0.
> Под `set -e` сценарий молча завершается. Безопаснее писать `((n += 1))` или `n=$((n + 1))`.

Аргументы: `$0` имя сценария, `$1` первый, `$#` их число, `${1:-default}` значение по
умолчанию. Проверки файлов: `[[ -f ]]` обычный файл, `-d` каталог, `-x` исполняемый, `-r`
читаемый. Ошибку пишем в stderr (`>&2`) и выходим с `exit 1`. В цикле по шаблону нужна
строка `[[ -f "$file" ]] || continue`, иначе на пустом каталоге в переменной окажется
сам шаблон `*.txt`. Отладка: `bash -n` проверяет синтаксис, `bash -x` печатает каждую
команду перед запуском.

## SSH

Клиент `ssh` на моей машине, сервер `sshd` на узле. Ключ: `ssh-keygen -t ed25519`, закрытый
`id_ed25519` с правами 600, открытый `.pub` уходит на сервер в `~/.ssh/authorized_keys`
(это делает `ssh-copy-id`). Каталог `~/.ssh` должен быть 700. Закрытый ключ с правами 644
клиент игнорирует: «UNPROTECTED PRIVATE KEY FILE».

При первом входе ssh показывает отпечаток ключа сервера. Его надо сверить, а не жать `yes`
вслепую. Сохранённые ключи лежат в `~/.ssh/known_hosts`: `ssh-keygen -F host` найти,
`ssh-keygen -R host` удалить. Изменившийся ключ хоста может значить подмену сервера.

`~/.ssh/config` с блоком `Host lab` заменяет длинную строку на `ssh lab`; итог настроек
показывает `ssh -G lab`. Удалённая команда: `ssh lab 'hostname; uptime'`. В одинарных
кавычках переменные раскрывает сервер, в двойных подставит локальный Bash ещё до отправки.

Копирование: `scp f lab:~/dir/`, `scp lab:~/f .`, `rsync -av ./ lab:~/project/` (второй
прогон rsync передаёт только изменившиеся файлы). Туннели: `-L 8080:localhost:80` мой порт
ведёт на порт сервера, `-R` наоборот, `-D 1080` SOCKS-прокси, `-J` через промежуточный узел;
`-N` без команды, `-f` в фон. Диагностика: `ssh -v`, `ss -ltn`,
`ssh -o BatchMode=yes lab true` (проходит ли вход по ключу без пароля).

## tmux

Сервер tmux держит сессии, пока они есть. Сессия содержит окна, окно делится на панели.
Закрытый терминал или оборванный SSH убивает только клиент, программы внутри живут дальше.

| Действие | Команда |
|---|---|
| новая сессия | `tmux new -s lab` |
| отсоединиться | `Ctrl+B`, затем `d` |
| список / вернуться | `tmux ls`, `tmux attach -t lab` |
| окно, панель | `Ctrl+B c`, `Ctrl+B %` (слева/справа), `Ctrl+B "` (сверху/снизу) |
| из сценария | `tmux send-keys -t lab:1.0 'date' Enter`, `tmux capture-pane -p` |
| удалить сессию | `tmux kill-session -t lab` |

Префикс нажимается и отпускается, потом вторая клавиша. `Ctrl+B x` закрывает панель вместе с
программой. Адрес панели `сессия:окно.панель`; окна по умолчанию нумеруются с 0, с 1 только
после `set -g base-index 1` в `~/.tmux.conf`. На слайде «применить: Ctrl+B, r», но по
умолчанию `r` это `refresh-client`, перечитывать конфиг он начинает только после
`bind r source-file ~/.tmux.conf`. Через SSH: `ssh -t lab 'tmux new-session -A -s work'`.

## Что взять с собой

Сначала справка и контекст (`type`, `help`, `pwd`, `ls -la`), переменные в кавычках, вывод
через `printf`, после сохранения проверка (`ls -l`, `file`, `bash -n`), долгая удалённая
работа в tmux. Автоматизировать имеет смысл то, что уже получилось руками.
