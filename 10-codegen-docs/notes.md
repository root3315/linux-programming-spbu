# Генераторы кода и документация

## Два шага: слова и грамматика

Строка `2+3*4` для программы — просто набор символов. Чтобы её посчитать, нужно два шага. Сначала
лексер режет текст на токены: число 2, плюс, число 3, звёздочка, число 4. Потом парсер
проверяет, что токены сложены по грамматике, и считает: `3*4` раньше сложения.

Лексер генерирует flex, парсер генерирует bison. Они не пишут программу за меня: я описываю
правила, они выдают C-код. В калькуляторе из архива `calc.l` 28 строк и `calc.y` 57, а
сгенерированные `lex.yy.c` и `calc.tab.c` занимают 1802 и 1347. Эти два файла не правят:
`make clean` удалит их, и любая правка пропадёт.

Сборка такая (она из `Makefile` архива, я её запускал):

```bash
bison -d calc.y      # calc.tab.c и calc.tab.h, в заголовке объявлен NUM
flex calc.l          # lex.yy.c
gcc -Wall -Wextra -O2 -Wno-unused-function -o calc calc.tab.c lex.yy.c -lm
```

> **Грабли:** порядок важен. `lex.yy.c` подключает `calc.tab.h`, а его создаёт `bison -d`.
> Если вызвать `flex` и `gcc` без него, gcc остановится на `fatal error: calc.tab.h: No such file
> or directory`.

## flex: образец и действие

Файл `.l` состоит из трёх частей, их разделяет `%%`: код на C в `%{ ... %}` и опции, правила,
свой C-код. Правило — это образец (регулярное выражение) и действие в фигурных скобках. Если
подходят несколько образцов, побеждает самое длинное совпадение, а при равной длине верхнее. Так
`12` остаётся одним числом: `[0-9]+` не останавливается на первой цифре. Это видно в трассе
`flex -d`: правило числа приняло `"12"` целиком.

Фрагмент `calc.l`:

```text
[0-9]+(\.[0-9]+)?   { yylval = atof(yytext); return NUM; }
[ \t]+              { /* пробелы просто пропускаем */ }
"+"                 { return '+'; }
.                   { return yytext[0]; }   /* всё остальное — как есть */
```

Число кладётся в `yylval`, и туда же парсер потом смотрит за значением токена. Правило `.`
отдаёт непонятный символ парсеру как есть, а ругается уже он. Поэтому `%` заработал в калькуляторе
даже без отдельной строки в `calc.l`.

Комментарии `#` до конца строки добавляются одним правилом, `"#".*`. Оно съедает хвост строки, но не
`\n`, так что строка по-прежнему заканчивается токеном.

## bison: правила и приоритеты

В `.y` слева от двоеточия стоит то, что получаем, справа — из чего. В фигурных скобках считаем значение:
`$$` — результат, `$1` и `$3` — части правой стороны. Фрагмент `calc.y`:

```text
expr:
      NUM                       { $$ = $1; }
    | expr '+' expr             { $$ = $1 + $3; }
    | expr '*' expr             { $$ = $1 * $3; }
    | '-' expr %prec NEG        { $$ = -$2; }
    | '(' expr ')'              { $$ = $2; }
    ;
```

Правило `error '\n'` в `line` превращает ошибочную строку в «не понял, попробуйте ещё», и разбор
идёт дальше. `2 + + 3` калькулятор переживает.

Приоритет задают строки в начале файла, чем ниже строка, тем операция старше:

```text
%left '+' '-'
%left '*' '/' '%'
%precedence NEG
%right '^'
```

`%left` значит левую ассоциативность (`10-2-3` — это `(10-2)-3`), `%right` — правую (`2^3^2` — это
`2^(3^2)`). `-2^2` я сделал равным -4, как в математике, поэтому `^` стоит ниже `NEG`, то есть старше
унарного минуса. Все эти значения проверены: `2 * 3 + 4` даёт 10, `10 - 2 - 3` даёт 5, `8 / 4 / 2`
даёт 1, `2 ^ 3 ^ 2` даёт 512.

> **Запомнить:** без `%left` bison не падает, а предупреждает: `40 shift/reduce conflicts`. Конфликты
> он решает сдвигом, и калькулятор считает неправильно: `2 * 3 + 4` даёт 14, `10 - 2 - 3` даёт 11.
> Сборка при этом проходит, предупреждение легко пропустить.

## Генератор или руками

В архиве есть тот же калькулятор без инструментов, `mini_calc.c`. Приоритет там задан вложенностью
функций: `parse_expr` зовёт `parse_term`, тот зовёт `parse_atom`.

| | flex и bison | руками |
| --- | --- | --- |
| Размер | 85 строк правил (по архиву) | 170 строк C |
| Новая операция `^` | 1 строка во flex, 2 в bison | новый токен, 2 функции, правка 3 вызовов: +26 строк |
| Плохой ввод `2 + + 3` | «не понял» | молча 5 |
| Сломать приоритет | `%left` убран: 40 конфликтов при сборке | вызовы заменены: другой ответ без слова |

Последнюю строку проверил: если `parse_expr` зовёт `parse_atom` вместо `parse_term`, то
`2 + 3 * 4` даёт 5, и компилятор говорит только про неиспользуемую функцию. Для маленького
неменяющегося формата хватит и рукописного разбора. Если грамматика растёт, нужен генератор.

## doxygen: сайт из комментариев

Doxygen читает исходники, берёт комментарии вида `/** ... */` и собирает html. Описание не
придумывается: нет комментария, нет описания. Команды в комментарии начинаются с `@`: `@brief` —
краткое описание, `@param` — параметр, `@return` — результат. Фрагмент из моего `mini_calc.c`:

```text
/**
 * @brief Поделить a на b без падения на нуле.
 * @param a делимое
 * @param b делитель; если 0, печатается сообщение
 * @return a / b или 0, если b равно 0
 */
double safe_div(double a, double b)
```

Настройки лежат в `Doxyfile`, запуск одной командой, результат в `docs/html`:

```bash
doxygen Doxyfile
```

В `Doxyfile` из архива важны `INPUT = calc handwritten`, `EXTRACT_ALL = YES` и
`EXTRACT_STATIC = YES`. Без `EXTRACT_STATIC` из списка пропали все функции с `static`, остался
один `main`. Описание у `main` появляется после `@brief` и исчезает, если комментарий убрать,
а сама функция в списке остаётся: на это работает `EXTRACT_ALL`.

> **Грабли:** `INPUT` включает папку `calc`, и если калькулятор уже собран, в документацию попадают
> и сгенерированные `lex.yy.c`, `calc.tab.c`, `calc.tab.h`. В репозиторий их, как и `docs/`,
> не кладу.

> **Запомнить:** сгенерированное не правят и не коммитят. В репо лежат `calc.l`, `calc.y`,
> `mini_calc.c`, `Doxyfile`, а `lex.yy.c`, `calc.tab.*`, бинарники и `docs/` каждый раз
> собираются заново.

## Запуск с нуля

Архив `chapter10.tar.gz` с примерами преподавателя в репозиторий не входит. Файлы в нём с
CRLF, сборка идёт и так, но свои копии я перевожу в LF. Проверка итогового калькулятора:

```bash
cd calc && make clean && make
printf '%s\n' '2 + 3 * 4' '(2 + 3) * 4' '-2 ^ 2' '10 % 3' '2 + 2 # коммент' | ./calc
```

```text
калькулятор: пишите выражения, Enter — посчитать, Ctrl+D — выход
= 14
= 20
= -4
= 1
= 4
```

Строки с `%` подаю через `printf '%s\n' ...`: в формате `printf` одиночный `%` значит подстановку.
