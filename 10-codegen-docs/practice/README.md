# Практики занятия 10

Четыре практики на одном проекте из архива преподавателя: калькулятор на flex и bison (`calc/`),
тот же калькулятор руками (`handwritten/mini_calc.c`) и `Doxyfile`. Каждая практика продолжает
предыдущую: файлы из одной папки с решением я брал за основу следующей. В папках ниже только
моё: изменённые файлы и сессии с командами и выводом.

## Подготовка

Архив скачивается и распаковывается так:

```bash
wget https://www.smartmelio.ru/chapter10.tar.gz
tar -xzvf chapter10.tar.gz
```

Получится `Chapter10/`. Всё проверял на Ubuntu 24.04 (flex 2.6.4, bison 3.8.2, doxygen 1.9.8,
gcc 13.3.0). Инструменты ставятся так:

```bash
sudo apt update
sudo apt install flex bison doxygen build-essential
```

Файлы в архиве с концами строк CRLF. Сборка идёт и так, `make` их не замечает, проверял. Свои
копии я всё равно перевожу в LF, чтобы дифф был чистым:

```bash
sed -i 's/\r$//' Doxyfile calc/calc.l calc/calc.y calc/Makefile handwritten/mini_calc.c handwritten/Makefile
```

Сборка калькулятора: `cd calc && make`. Строки с `%` в `printf` подаю как `printf '%s\n' '10 % 3'`,
иначе `printf` примет `%` за подстановку.

Сгенерированное (`lex.yy.c`, `calc.tab.c`, `calc.tab.h`, бинарники `calc` и `mini_calc`, папка
`docs/`) в репозиторий не кладу: оно создаётся заново командами `make` и `doxygen`.

## Практика 1. Слова: flex

Собрать калькулятор, проверить `2+3*4` (должно быть 14), посчитать строки сгенерированного
`lex.yy.c`. Добавить правило для комментариев `#` (на слайде «строки, начинающиеся с `#`», а
проверка `2+2 # моё`, значит, комментарий в хвосте строки тоже нужен), пересобрать и убедиться, что
`12` остаётся одним числом. Заодно проверил `2 + + 3` и `1 / 0`.

Решение: [01-lexer/session.md](01-lexer/session.md), мой [calc.l](01-lexer/calc.l).

## Практика 2. Операция %

Добавить остаток от деления. Нужно тронуть оба файла: правило в `calc.l`, токен и правило с
`fmod` в `calc.y`, `%` в строку приоритета `*` и `/`, пересборка с нуля. Проверить `10 % 3` и
`10 / 3`, выяснить, что будет при `10 % 0`, и убедиться, что bison не жалуется на конфликты.

Решение: [02-modulo/session.md](02-modulo/session.md), мои [calc.l](02-modulo/calc.l) и
[calc.y](02-modulo/calc.y).

## Практика 3. Генератор или руками

Посчитать `wc -l` у `calc.l`, `calc.y`, `mini_calc.c` и узнать, во сколько раз ручной вариант
длиннее правил. Добавить степень `^` в оба варианта и сравнить, где проще. Убрать `%left` из
`calc.y` и посмотреть, что скажет bison. Поменять местами вызовы в ручном разборе и посмотреть, что
изменится в ответах. Записать вывод, какой подход выбрал бы. `%` в ручной вариант я не добавлял:
по заданию он нужен только в `calc`, так что `10 % 3` в `mini_calc` даёт 10.

Решение: [03-compare/session.md](03-compare/session.md), мои [calc.l](03-compare/calc.l),
[calc.y](03-compare/calc.y) и [mini_calc.c](03-compare/mini_calc.c).

## Практика 4. Своя документация

Собрать `doxygen Doxyfile` как есть, найти список функций на странице `mini_calc.c`, добавить
`@brief` к `main`, пересобрать и найти описание. Убрать `EXTRACT_STATIC` и посмотреть, что стало со
списком. Сделать функцию с `@param` и `@return`. Убрать комментарий и убедиться, что описание
исчезло. Страницы проверял командой `grep` по html.

Решение: [04-doxygen/session.md](04-doxygen/session.md), мой [mini_calc.c](04-doxygen/mini_calc.c).

## Где слайд и реальность расходятся

В `session.md` это отмечено на месте, здесь только цифры. Строк в исходниках из архива: `calc.l`
28 (на слайде 30), `calc.y` 57 (60), `mini_calc.c` 170 (200), `lex.yy.c` 1802 (1794). `10 / 3` печатает
3.33333, а не 3.33. Без `EXTRACT_STATIC` страница не пустая: остаётся `main`.
